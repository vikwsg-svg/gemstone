Authentication and sandbox

Two kinds of keys.

  • gsk_test_ keys run against synthetic stones. Every response says synthetic_data: true.
  • gsk_live_ keys run against the production engine.
  • Send keys as Authorization: Bearer <key>. Keys are scoped per product.
  • Errors always have the same shape: {{"error": {{"code", "message"}}}}.
Safe by design

Retries, versions and floors.

  • Idempotency keys on every POST: a retried request returns the original result and is billed once.
  • Model version pinning per request or per account; every response is stamped.
  • The 5-comp floor: status: insufficient_data and price: null when fewer than five comparables qualify.
  • Realized vs asking on every comparable, via source_type.

Batch

Revalue a whole portfolio from a spreadsheet.

Upload a CSV with variety, carat and shape (plus any optional columns), poll the job, and download one result row per stone with its band, confidence and valuation ID. A whole batch is pinned to one model version.
